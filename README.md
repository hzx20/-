# 教资刷题

教师资格证笔试备考小程序。微信搜一搜可搜到的免费刷题工具。

一个人做的小程序：题库自建、判分离线、云开发免服务器、广告变现走激励视频。

---

## 这是什么

一个给考教师资格证的人用的刷题小程序。核心功能是四块：

| 功能 | 解决什么问题 |
|---|---|
| 刷题 | 按科目、按章节刷，主观题自动判分并给评分点反馈 |
| 错题本 | 做错自动收录，做对自动移出，永远是"还没掌握"的题 |
| 数据 | 7 天趋势、分模块正确率，低于 60% 的模块标红 |
| 模考 | 限时答题，练真实考试的节奏感，交卷后出成绩 |

## 技术栈

- **小程序**：微信原生框架 + 微信云开发
- **判分**：纯本地算法，主观题按评分点关键词命中率折算
- **云端**：3 个云函数（登录、记录上报、数据统计）
- **变现**：微信流量主，激励视频为主

没上跨端框架（Taro/uni-app）、没有 UI 库、没有构建工具。
理由是个人开发者零资源时，依赖越少越稳，审核也最不容易被拒。

## 本地跑起来

### 1. 装微信开发者工具

去 https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html 下载，
选"小程序"版本。

### 2. 导入项目

- 打开开发者工具 → 导入项目
- 目录选本项目根目录（有 `project.config.json` 的那一层）
- AppID 填自己的，或先用"测试号"

### 3. 跑测试

代码里所有核心逻辑都不依赖微信环境，可以直接在命令行验证：

```bash
# 题库格式校验
python tools/validate_bank.py

# 判分逻辑（73 项）
node tools/test_grade.js

# 存储逻辑（55 项）
node tools/test_store.js

# 云调用与广告降级（34 项）
node tools/test_cloud_ad.js

# 项目完整性（路由、事件绑定、乱码、JSON 语法）
python tools/check_project.py
```

**改完代码先跑这三条**，比在开发者工具里点快得多。
这套脚本抓到过几个界面上完全看不出来的 bug（正确率翻倍、
登录永久失效、短答案判不了分）。

### 4. 配置云开发（可选）

不做这一步也能正常刷题，所有功能在本地跑。
只做数据同步和后台统计时才需要。见 [docs/云开发配置.md](docs/云开发配置.md)。

### 5. 加题库

题库是纯 JSON，**改之前先查，改之后再导**，顺序不能反：

```bash
# 1. 把新题存成 JSON，先做六项自查
python tools/check_new_questions.py 待导入.json

# 2. 自查通过再导入
python tools/add_questions.py 待导入.json

# 3. 导入后必跑
python tools/validate_bank.py    # 格式
python tools/bank_stats.py       # 难度分布
```

六项自查专治肉眼看不见的问题。前几批出题每批都被它逮到过：
混入英文单词、判断题答案写成 `[True]`、材料题漏参考答案、
id 与单选题撞号、中文引号转义被 shell 还原、中文引号嵌套错误、
以及最危险的**考点和已入库题目重复** —— 用户刷到重复题会以为程序坏了。

查重报出的是「疑似」，每一处仍需人工核对题干和答案。
加新科目请看 [miniprogram/data/README.md](miniprogram/data/README.md)。

## 核心设计说明

### 主观题怎么判分

材料分析题和写作题没有标准选项，判分是本项目最需要解释的部分。

做法是**评分点命中匹配**：

1. 事先把参考答案拆成若干评分点（`points` 数组）
2. 学生作答后，文本切成 3 字滑动片段
3. 每个评分点也切成同样规格的片段，算命中率
4. 平均命中率 × 100 = 参考得分，60 分及格

几个关键取舍：

- **为什么用滑动片段而不是分词**：中文词长不固定，
  第一版用正则切词块，结果 `学生学习的引导者和促进者` 被切成
  `学习引导促` / `进者` 这种碎片，和评分点完全对不上。
  改用滑动片段后，`引导者`、`促进者` 能原样出现。
  两边用同一个切法，比较的就是同一套片段。
- **为什么片段长度自适应**：固定 3 字的话，
  学生答"教师是引路人"（6 字）还能切，
  但只答 4 字就一个片段都产不出来，会被判 0 分。
  短文本降级用 2 字片段。
- **为什么不是 AI 判分**：见下面的"预留的 AI 接口"。

**局限要主动说清**：这是关键词命中率，不是语义理解。
写得通顺但跑题的答案可能误判得高分。
所以 UI 上写的是"参考得分"，并把评分点逐条展示，
让学生自己判断有没有答到。这个在面试里主动讲，
比被面试官问出来好。

### 预留的 AI 接口

`core/grade.js` 里的 `gradeByAI()` 和 `cloud.js` 的 `callAI()` 已就位，
默认关闭（`config.aiGrade.enabled = false`）。

不默认开启的三个理由：

1. 微信审核对调用外部 AI 接口管得较严，个人主体有被拒风险
2. 每次调用都花钱，500 UV 之前没收入，投入产出比为负
3. 关键词命中率已能给出可用的参考分，不接也不影响留存

接入时只需三步：部署 `gradeByAI` 云函数 → 填 API Key → 把开关改 true。
页面代码一行都不用动。

### 降级策略

云端挂了、广告没开通，用户照样能刷题。

`core/cloud.js` 里所有函数失败都返回默认值而非抛错，
`core/ad.js` 里广告不可用时直接当"看完了"处理。

这条原则是有测试保障的（`tools/test_cloud_ad.js` 34 项），
因为这类代码看起来没问题，但云函数没部署时页面白屏，
用户直接卸载——而这种问题在开发阶段往往发现不了。

## 广告变现

收益排序：激励视频（eCPM 50-120 元）> 插屏（15-40）> banner（8-20）。

当前状态：**未开启**。需要累计 500 个独立访客（UV）才能申请流量主。
注意 UV 是"访问过的不同用户数"，同一个人反复打开只算 1 个。

激励视频放在两个位置，都是用户主动点击：

- 首页每日推荐题目旁
- 模考交卷后"解锁完整解析"

广告未开通时 `adsEnabled = false`，相关 UI 不渲染，流程不卡住。

开通步骤见 [docs/上线检查清单.md](docs/上线检查清单.md)。

## 冷启动

个人开发者唯一可持续的免费流量是微信搜一搜自然搜索。
SEO 配置见 [docs/SEO配置清单.md](docs/SEO配置清单.md)。

核心是砍到单点极致：一个证种、一条功能主线。
不要做成"考试大全"——那是已有大厂产品的战场。

## 数据与隐私

- 用户作答进度存在本地（微信 Storage），不上传
- 开启云开发后，答题记录同步到云数据库用于统计
- 不收集任何个人身份信息，不需要手机号，不需要位置
- 不接入任何第三方 SDK
- 清除数据：我的 → 清除全部数据
