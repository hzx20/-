"""出题工具注意事项（踩过的坑，别再踩）

1. 【别用 Bash heredoc 写复杂 Python】
   shell 会把\\" 还原成裸 "，中文内容里一混就是
   SyntaxError: invalid character '，'
   复杂脚本一律用 Write 工具写文件。

2. 【中文引号统一用「」】
   用「」就不会和 shell、JSON 转义打架。

3. 【判断题答案格式】
   现有题库约定是 ["A"] 或 ["B"]，不是 [True] / [False]。

4. 【材料题必须同时有 answer 和 points】
   answer = 参考答案要点（给用户看的）
   points = 评分点（判分引擎靠关键词命中用）
   两个都要有，缺一个都会被 add_questions.py 拦下。

5. 【材料题题干必须含明确提问】
   含"请结合...分析"这类句式，否则用户不知道要答什么。

5.5 【★ 材料题的 points 不是关键词，是完整解析段落】★最容易搞错的一步
   正确约定：
     answer[i] = 第 i 个答案要点（一句话概括）
     points[i] = 对应这个要点的**完整解析段落**（40-90 字），与 answer 一一对应

   我第一次写成扁平关键词列表直接报错：
     ['素质教育观', '以学生为本', '面向全体学生', ...]
     -> AssertionError: 参考答案(4)与评分点(10)数量不一致

   为什么必须写长段落？ 看 grade.js 的判分逻辑：
     它把 points 切成 2-3 字连续片段，再用**字符覆盖率**判断命中：
       评分点 "教师是学生学习的引导者" 共 12 字，
       学生答案里出现其中 9 个连续字，覆盖率 75%，就算命中。

   所以 points 写长反而更准 —— 它包含大量可被命中的实词片段。
   如果只写「素质教育观」4 个字，学生答出这 4 个字就满分，
   根本区分不出「答得对」和「蒙对了术语」，就失去了区分度。

   写评分点的四条要求：
     ① 与 answer 数量相同、顺序对应
     ② 每段 30 字以上（脚本已加assert 拦截）
     ③ 段内必须包含该要点的核心实词（学生答到就该命中）
     ④ 不写"答出第二点"这类无实词的过渡语

5.6 【★ 材料题必须验判分区分度】自查工具查不到这层
   六项自查只查格式，**查不出判分引擎能不能有效区分**。
   出完材料题必须用真实 grade.js 跑三种水平的学生答案：

   优等生（踩点作答）→ 应得 9 分左右
   中等生（答到一半）→ 应得 4 分左右
   差生（胡乱堆词）→ 应得 1 分左右

   如果差生和优等生得分接近，说明 points 写得太泛，区分度不足，要重写。
   实测脚本（注意函数名是 gradeSubjective，不是 gradeEssay）：
     const r = require('./miniprogram/core/grade.js').gradeSubjective(q, ans);
     // 返回 { score, total, details }，注意 hit 字段不存在

6. 【id 段位规划】
   单选：xxxL判断：xxxC（用独立段如120C/121C，别和单选撞号）
   材料：xxxM

   ★ **出题前必须先查题库现有最大编号**：
   ```bash
   python -c "import json,io; print(max(int(q['id'].split('-')[1][:3]) for q in json.load(io.open('miniprogram/data/subject2.json',encoding='utf-8'))['questions']))"
   ```
   实际踩坑：批次 8 用了 s2-220M~228M，批次 9 接着写就又用了 228M，
   被自查工具撞号检查抓到。**不能凭记忆接着往下数。**

6.5【★ 测出区分度不理想时，必须当成不合格重写】
   区分度不合格的典型信号：**差生得分 ≈ 中等生得分**。
   实测遇到过 4/1/1 分的情况（满分 10），当时差点用
   「这道题要点少、满分本来就低」当理由放过 —— **这是自我欺骗**。

   正确做法：查根因（通常是评分点解释性太强、核心实词密度不够），
   把answer 改成实词化的核心判断句，再重测。
   同一道题改完复测得到 8/6/4 分，才算合格。

   **判定标准**：优等生与中等生应相差 2 分以上，
   中等生与差生也应拉开差距。三档挤在一起就是题目废了。

7. 【难度标准】
   难度 1 = 名称/归属/定义，记住即可
   难度 2 = 理解后比较或应用
   难度 3 = 综合多个知识点
   材料分析题统一难度 3

8. 【出题流程：先查后导，顺序不能反】
   python tools/check_new_questions.py 待导入.json
   python tools/add_questions.py 待导入.json

9. 【不删旧题，只删新题】
   旧题已入库，用户可能有练习记录，删了会导致记录错位。

10. 【id 前缀必须与所在科目一致】
    题库里出现过 s2-402L 混在 subject1.json 的 law 模块里。
    单看每个文件都合法（不重复、不撞号），但跨科目统计会把它算错科目，
    去重也会漏检 —— **这类错误只有跨文件比对才看得出来**。
    check_new_questions.py 已加检测，会报「id 前缀与科目不符」。

11. 【函数签名要少传参数】
    出题脚本第一版让每题手写 module 和 source 参数，
    结果 16 道题全部漏传、逐个报错。
    改成用 MODULE_S1[id] 字典按 id 取模块，从调用处消除传错的可能。
    **能自动推导的参数就别手写。**
